`codex/pasteferry-2.9.0`.

## Issue found during repeated testing

An earlier CI run, [41769590793](https://github.com/baiyuze/pasteferry/actions/runs/41769590793),
failed `TestAddFriendViaServer` in both Linux jobs. Ten local repetitions could
pass, while a longer 50-repetition Linux run reproduced the failure.

A delayed pairing-purpose reply from a preceding device-pairing attempt could
mark a pending attempt as already evaluated. A later friend/device purpose
mismatch was then ignored. Commit `53ee171d` changes `evaluateIntent` to verify
that the pending entry is still current, accept later mismatches even after an
earlier matching reply, and close the purpose notification channel only once.

The deterministic regression test
`TestPairingRejectsFriendIntentAfterEarlierDeviceIntent` failed before the fix
and passed afterward. Verification included:

- Targeted macOS race tests, 20 repetitions.
- The complete macOS peers package.
- Linux targeted friend-pairing and deterministic regression tests, 100 repetitions.
- The complete nine-job CI run for the fixed source commit.
- The installed cross-platform workflows and recovery checks listed above.

## Coverage limits

- No Apple Silicon Mac was available for a native arm64 installation/runtime
  test. Its package architectures and signatures were checked.
- Linux arm64 built and passed its native CI tests. No local arm64 Linux VM
  installation was performed.
- Linux installed GUI/clipboard tests used X11/Xvfb. An interactive Wayland
  desktop regression was not performed.
- Android CI build, compatibility tests and API checks passed. The downloaded
  APK was not installed on an Android device during this validation.
- Quick-paste session/hotkey readiness and reconnection were verified; this
  does not assert automatic pasting into every possible foreground application.
- Production auto-update application was not performed, because release and
  update publication are explicitly paused.
