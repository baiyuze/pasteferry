# 排障

[English](troubleshooting.md) · [回到 README](../README.zh-CN.md)

**服务中转不可用或额度用尽**
双方都需要 2.1.0 或更新版本，并主动开启「服务」。在「服务」页检查更新时间、重置时间与原因。中转额度北京时间零点重置，直连不扣额度；后台调整策略后，运行中的客户端会刷新用量，无需重启。自建地址在「保存并连接」后生效。

**同一网络里找不到另一台电脑**
先确认两台都启用了后台同步、连着同一个网络。公司里有线和无线、访客网络、开了「AP 隔离」的 Wi‑Fi 常常不互通：在输入配对码的那台点「不在同一网段？」，填上对方配对码下面显示的地址。还是找不到就看对方的防火墙：Windows 上在「设置 → 局域网」里点「放行」（会请求一次管理员权限）；Mac 上到「系统设置 → 隐私与安全性 → 本地网络」打开 PasteFerry Daemon。`pasteferry-cli nat` 的「局域网」一节能看到本机的端口、发现了几台隔空贴、每台设备能否找到、记住了哪些地址。见[同一网络教程](https://pasteferry.cc/lan/)。

**「设置 → 连接状态」一直是「未连接」**
只在填了服务器地址时才有这个问题；同一网络里不需要服务器，地址留空即可。先核对地址：以 `ws://` 开头、端口 8787、以 `/signal` 结尾；再在这台电脑的浏览器里打开 `http://<服务器地址>:8787/healthz`。打不开说明到服务器的网络不通：服务器没在运行、那台电脑睡眠了、被防火墙拦住了，或者它的地址变了。Windows 与 Linux 的安装脚本会给出需要的防火墙命令，见[服务器部署说明](../server/deploy/README.md)与[局域网部署教程](https://pasteferry.cc/server/)。

**国内云服务器：填域名连不上，填 IP 能连**
域名没有备案时，国内云厂商会拦截访问它的明文 HTTP 请求，任何端口都一样，返回一个跳转到拦截页的响应。WebSocket 握手就是明文 HTTP 请求，所以同样被拦。地址里直接填 IP（`ws://<服务器IP>:8787/signal`），或者给域名备案。见[公网服务器部署教程](https://pasteferry.cc/cloud/)。

**用 Tailscale 时显示「直连」，传输却很慢**
「直连」指两台电脑在 Tailscale 的虚拟网里直接相连。Tailscale 自己打不通两台电脑时，会经它在境外的中转服务器（DERP）转发，在国内用就会慢。运行 `tailscale ping <对方>`：显示 via DERP 说明 Tailscale 在中转，显示 via <IP>:<端口> 才是点对点。见 [Tailscale 教程](https://pasteferry.cc/tailscale/)。

**UU 远程开启时不断新增 `.uuremote_…` 文件记录**
升级两端客户端到 1.3.2 或更新的版本。UU 远程会把临时占位文件写入系统剪贴板，旧版隔空贴会把它们当成普通文件再次转发。新版在扫描、入库和发送之前过滤已确认的 `.uuremote_aeawv` 加数字命名；混合选择保留正常文件，接收端忽略纯占位记录，启动时清理历史里的纯占位记录（不删除 UU 的源文件）。普通空文件、隐藏文件和大文件不受这条规则影响。50 MB 是自动传输阈值，不是故障原因；无需关闭 UU 的 UDP P2P。其他剪贴板同步工具仍可能造成普通内容重复，可只保留一个工具负责剪贴板同步。技术与验证记录见 [UU 远程兼容修复](../design/uu-remote-clipboard.md)。

**剪贴板读不到内容，`pbpaste` 也是空的**
系统的剪贴板服务可能卡住了：某个程序声明了剪贴板内容后异常退出，会留下一个"有类型声明、没有数据"的空壳。执行 `killall pboard`，再复制一次即可。

**设备一直显示「离线」**
在同一网络里：看上面「同一网络里找不到另一台电脑」。两台都换过地址时，在设备列表里点那台设备的「…」菜单，选「输入它的地址」。跨网络时：检查两台电脑的 **设置 → 连接状态** 是否都是「已连接」，不是的话确认服务器地址正确、8787 端口可以访问。

**一直显示「中转」而不是「直连」**
刚连上时显示中转、过一会儿变成直连是正常的：先用中转保证能用，空闲时再换直连。一直是中转，说明 NAT 打洞没成功，常见于端口随机分配的 NAT 或严格的防火墙。功能不受影响，只是速度受服务器带宽限制。运行 `pasteferry-cli nat` 看本机探测到了几个出口：出口为 0 说明 UDP 被拦截了。

**查看日志**
后台服务的日志：Mac 上在 `~/Library/Logs/PasteFerry/daemon.log`，Windows 上在 `%LOCALAPPDATA%\PasteFerry\logs\daemon.log`。服务器的日志：Linux 上用 `journalctl -u pasteferry-server -f` 查看，Mac 上在 `~/Library/Logs/PasteFerry/server.log`，Windows 上在 `C:\ProgramData\PasteFerry Server\server.log`。

## 已知限制

- **没有经过 Apple 公证，Windows 版也没有代码签名**，第一次打开时需要手动放行一次。
- **Windows 上不支持「虚拟文件」**：从 Outlook 附件、压缩包里直接复制的文件，剪贴板里没有真实路径，不会同步。先保存或解压出来再复制即可。
- **Mac 版还不会跳过密码管理器复制的内容**，Windows 版已经会。
- **对方离线太久的内容不会补发**。服务器不存数据；对方暂时连不上时，本机只在内存里记下最近 20 条（24 小时内的），本机的后台服务重启后就清空了。
- **中转模式的速度取决于服务器带宽**。直连时不受影响。
- **不在同一网段、两台都换了地址时**，要在设备菜单里重新输入一次地址；隔空贴不扫描网段。两台都是没放行防火墙的 Windows、又只有一边知道对方地址时连不上，要在被连的一方点「放行」。
- **macOS 15 要允许「本地网络」权限**，否则后台服务连不到局域网里的设备（对方先发来时仍能连上）。更新到新版本后，最初十几秒的包也可能被系统拦下，之后自动恢复。
