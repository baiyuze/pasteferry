隔空貼

運作原理

按下複製之後發生了甚麼，兩部電腦怎樣找到彼此、怎樣直連，打不通時怎麼辦。

按下複製之後

文字、圖片、檔案、整個資料夾，都走同一條路。

  1. 偵測

    在 Mac 上，背景服務每隔一小段時間查看一次剪貼簿的變更計數，只看計數和類型，不需要授權，也不會彈出系統提示；在 Windows 上，複製的一刻系統就會通知它。

  2. 傳輸

    文字隨訊息一起發出；50 MB 以內的圖片和檔案打包成串流即時推送；更大的檔案只發送一條記錄，等你需要時再傳。

  3. 貼上

    另一部電腦先把內容存到本機，再寫入剪貼簿。按下 ⌘V 或 Ctrl+V 貼上的，就是本機上的真實檔案。

隔空貼的連線方式

同一網絡裏，裝置無需伺服器就能找到彼此；跨網絡時，官方服務或自建伺服器協助交換連線資料。優先打洞直連，失敗後才使用加密中轉。下圖展示通用的信令與中轉結構。

公司網絡也能直連

公司雙線、電訊商地址池這類網絡有多個出口，會按目標地址選擇走哪一個。只探測一次只會知道其中一個出口，結果只能經伺服器中轉。隔空貼會探測每個出口，把所有地址都告訴對方。

做了甚麼

  • 共用一個端口。所有連線都從同一個本機 UDP 端口收發，向不同伺服器查到的地址才能對得上。
  • 探測每個出口。在這個端口上同時詢問 7 部 IP 分散的伺服器，網絡有幾個出口就取得幾個地址；受 DNS 污染的地址會先過濾掉。
  • 全部告訴對方。對方逐個嘗試，與實際出口吻合的那一個就能打通。
  • 記住見過的出口。某次漏掉的出口如果沒有改變端口，就用「出口 IP + 本機端口」推算補上。
  • 定好誰先發封包。有些路由器收到對方先到的封包，會佔用該端口。一方先公佈出口地址，另一方先向那邊發封包，再公佈自己的；重試時兩種次序輪流使用。
  • 閒置時重試直連。直連失敗且中轉可用時，先透過中轉保持同步。連線閒置時可重試打洞，成功後切回直連並釋放中轉。

用真實的網絡拓撲驗證

NAT 打洞實驗室用 Linux 網絡命名空間與 iptables 搭建這些拓撲，用隔空貼真實的連線程式碼逐一執行，每次提交程式碼都會自動執行。

出問題時會怎樣

每個人的網絡環境都不同。以下這些情況都考慮過，也都有對應的測試。

在同一網絡裏找不到對方
不同網段、訪客網絡、開啟了 AP 隔離的 Wi‑Fi 會阻礙區域網絡發現。配對時輸入對方配對碼下面顯示的地址就可以；之後地址會被記住，兩邊都換了地址時，在裝置列表裏為它重新輸入一次。
系統阻擋區域網絡
由 macOS 15 起，背景服務連接區域網絡裏的裝置需要你允許；Windows 第一次執行時會詢問防火牆設定。未允許時 App 會提示，並提供直達設定的按鈕。
兩部電腦打不通直連
官方模式在直連失敗後，按目前額度申請中轉；自建模式使用自己的 TURN 中轉。兩種方式的內容均保持端到端加密。
公共 STUN 伺服器連不上
在內地連公共 STUN 時通時斷。伺服器自帶 STUN，用戶端會優先使用它。
從中轉切回直連
直連失敗且中轉可用時，先透過中轉保持同步。連線閒置時可重試打洞，成功後切回直連並釋放中轉。
對方進入睡眠、斷網或重新啟動
連線悄悄斷了也能察覺，會立即關閉並重新連線。這期間複製的內容會記下來，連上後補發到對方的複製記錄裏，但不會覆蓋對方此刻剪貼簿裏的內容。
伺服器斷線
自動重新連線，間隔由 1 秒開始倍增、最長 30 秒，並加入隨機抖動，避免大量裝置同時重新連線。同一網絡裏的裝置不受影響，照常同步。
檔案太大
超過上限的只同步一條記錄，需要時再拉取。拉取時如果來源檔案已被刪除，會清楚告訴你，而不是莫名其妙地失敗。
貼到只接受純文字的地方
從網頁複製的帶格式文字會同時寫入 HTML 和純文字兩份，貼到哪裏都不會冒出標籤。
檔案名稱在 Windows 上不合法
Mac 上可以用的冒號、問號等字元，收到時會換成對應的全形字元，名稱照樣看得懂；只差大小寫的兩個檔案也不會互相覆蓋。
複製的是密碼
在 Windows 上，密碼管理工具複製的內容會帶有「不要記錄」的標記，隔空貼看到就會略過：不同步，也不加入複製記錄。
仍未授權讀取剪貼簿
不會去讀取內容，否則背景程序會卡在一個看不見的系統彈出視窗上。App 裏會提示你授權，並提供直達設定的按鈕。
背景服務崩潰
Mac 上由系統的 launchd、Windows 上由隔空貼自帶的守護程序自動重新啟動，有 10 秒節流，不會無止境地重新啟動。
更新了 App，或者移動了它的位置
開啟 App 時會自動修正登入項目，並把背景服務重新啟動到新版本。

技術規格

版本2.4.2，2026 年 10 月 22 日發佈
Mac 用戶端macOS 13 Ventura 或以上；Apple 晶片與 Intel 處理器的 Mac 各有一個安裝檔，約 25 MB，不需要 Rosetta；另有兩種 Mac 通用的版本，約 47 MB
Windows 用戶端Windows 10 與 Windows 11，x64；為目前用戶安裝，不需要管理員權限；安裝檔約 23 MB
Linux 用戶端x64 與 ARM64；.deb（Debian、Ubuntu 等）或 tar.gz（其他發行版），約 22 MB；需要 X11 桌面，或帶 XWayland 的 Wayland 桌面（GNOME、KDE 等預設都已包含）；GTK 3
伺服器只在自建時需要部署；使用官方服務無需自備伺服器。自建支援 Linux x86_64/ARM64、macOS 與 Windows 10/11 x64。
介面語言簡體中文、繁體中文（台灣、香港）、English、日本語，預設跟隨系統，可在設定裏切換
同步的內容純文字、帶格式的文字、圖片與截圖、檔案、資料夾，可以按類型關閉
傳輸WebRTC 數據通道，直連優先，打不通時經 TURN 中轉；同一網絡裏經 mDNS 發現、UDP 8788 交換連線資訊；多出口網絡會逐一探測每個出口；檔案以 tar + zstd 串流方式打包
加密與身份DTLS 端對端加密；裝置身份為 Ed25519 密鑰；信令訊息逐條簽名
配對6 位配對碼，5 分鐘內有效，字元集剔除了 0/O、1/I 等容易混淆的字元；配對時人手核對安全指紋
自動同步上限預設 50 MB，可在 1 MB 到 1 GB 之間調整
記錄保留預設 3 天，可在 1 小時到 30 天之間調整，到期自動清理
實測速度區域網絡直連傳輸 20 MB 檔案約 330 毫秒，校驗和一致
技術架構背景服務與伺服器用 Go（Windows 上以純 Go 呼叫 Win32，Linux 上以純 Go 使用 X11 協定），介面用 Flutter（三個系統共用一套程式碼），訊息定義用 Protocol Buffers
