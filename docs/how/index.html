隔空贴

工作原理

按下复制之后发生了什么，两台电脑怎样找到彼此、怎样直连，打不通时怎么办。

按下复制之后

文字、图片、文件、整个文件夹，都走同一条路。

  1. 察觉

    Mac 上，后台服务每隔一小段时间看一眼剪贴板的变更计数，只看计数和类型，不需要授权，也不会弹出系统提示；Windows 上，复制的那一刻系统就会通知它。

  2. 传输

    文本随消息一起发出；50 MB 以内的图片和文件打包成流立即推送；更大的文件只发一条记录，等你需要时再传。

  3. 粘贴

    另一台电脑先把内容存到本地，再写入剪贴板。按下 ⌘V 或 Ctrl+V 粘贴出来的，就是本地的真实文件。

隔空贴的连接方式

同一网络里，设备无需服务器就能找到彼此；跨网络时，官方服务或自建服务器帮助交换连接信息。优先打洞直连，失败后才使用加密中转。下图展示通用的信令与中转结构。

公司网络也能直连

公司双线、运营商地址池这类网络有多个出口，按目标地址选走哪一个。只探测一次只会知道其中一个出口，只能经服务器中转。隔空贴会探测每个出口，把地址都告诉对端。

做了什么

  • 共用一个端口。所有连接从同一个本地 UDP 端口收发，向不同服务器问到的地址才对得上。
  • 探测每个出口。在这个端口上同时询问 7 台 IP 分散的服务器，网络有几个出口就拿到几个地址；被 DNS 污染的地址先过滤掉。
  • 全部告诉对端。对端逐个尝试，与实际出口吻合的那一个能打通。
  • 记住见过的出口。某次漏掉的出口如果不改端口，就用「出口 IP + 本地端口」推算补上。
  • 定好谁先发包。有的路由器收到对方先到的包会占住端口。一方先公布出口地址，另一方先往那边发包再公布自己的；重试时两种顺序轮流用。
  • 空闲时重试直连。直连失败且中转可用时，先通过中转保持同步。连接空闲时可重试打洞，成功后切回直连并释放中转。

用真实的网络拓扑验证

NAT 打洞实验室用 Linux 网络命名空间与 iptables 搭出这些拓扑，用隔空贴真实的连接代码各跑一遍，每次提交代码都自动运行。

场景结果
单出口 ↔ 家用路由器直连
两个出口，旧版本（对照）中转
两个出口 ↔ 家用路由器直连
四个出口 ↔ 家用路由器直连
两个出口，第二条没探测到，没有历史中转
两个出口，第二条没探测到，有历史直连
两个出口 ↔ 两个出口直连
两个出口 ↔ 端口随机分配的 NAT中转
一开始打不通，之后网络恢复先中转，随后直连
公司路由器会为外来的包占住端口直连
家用路由器会为外来的包占住端口先中转，重试一次后直连
没有服务器，同一网段，靠 mDNS 发现直连
没有服务器，两个网段，一边记得对方地址直连
没有服务器，两台都挡入站连接，都记得地址直连
没有服务器，两台都挡入站连接，只有一边记得连不上（已知限制）
没有服务器，两个网段之间被隔离连不上

实测：一台在 4 个出口的公司网络里的 Mac 与家里的 Mac，改造前只能中转，速度被服务器带宽限制在 0.6 MB/s；改造后直连，连上服务器后约 3 秒建立。

测量过程、设计取舍与踩过的坑见技术方案。

出问题的时候会发生什么

每个人的网络环境都不一样。下面这些情况都考虑过，也都有对应的测试。

同一网络里找不到对方
不同网段、访客网络、开了 AP 隔离的 Wi‑Fi 会挡住局域网发现。配对时输入对方配对码下面显示的地址就行；之后地址会被记住，两边都换了地址时，在设备列表里给它重新输入一次。
系统拦着局域网
macOS 15 起，后台服务连接局域网里的设备要你允许；Windows 第一次运行时会问防火墙。没放行时 App 会提示，并给出直达的按钮。
两台电脑打不通直连
官方模式在直连失败后，按当前额度申请中转；自建模式使用自己的 TURN 中转。两种方式的内容均保持端到端加密。
公共 STUN 服务器连不上
国内访问公共 STUN 时通时断。服务器自带 STUN，客户端优先用它。
从中转切回直连
直连失败且中转可用时，先通过中转保持同步。连接空闲时可重试打洞，成功后切回直连并释放中转。
对方睡眠、断网或重启
连接悄悄断了也能发现，立即关闭重连。这期间复制的内容会记下来，连上后补发到对方的复制记录里，但不会覆盖对方此刻剪贴板里的内容。
服务器断开
自动重连，间隔从 1 秒开始翻倍、最长 30 秒，并带随机抖动，避免一群设备同时重连。同一网络里的设备不受影响，照常同步。
文件太大
超过上限的只同步一条记录，需要时再拉取。拉取时源文件已经被删，会明确告诉你，而不是不明不白地失败。
传文件时断开
隔空传送传到一半断网、睡眠或程序退出，30 分钟内连上会从断点自动接着传；更晚的话点「继续」，同样从断点开始。每个文件都校验，不完整的不会出现在保存位置。
粘贴到只认纯文本的地方
从网页复制的带格式文字会同时写入 HTML 和纯文本两份，粘贴到哪里都不会冒出标签。
文件名在 Windows 上不合法
Mac 上可以用的冒号、问号等字符，收到时换成对应的全角字符，名字照样看得懂；只差大小写的两个文件也不会互相覆盖。
复制的是密码
Windows 上，密码管理器复制的内容会带一个「不要记录」的标记，隔空贴看到就跳过：不同步，也不进复制记录。
还没授权读取剪贴板
不去读内容，否则后台进程会卡在一个看不见的系统弹窗上。App 里会提示你去授权，并给出直达按钮。
后台服务崩溃
Mac 上由系统的 launchd、Windows 上由隔空贴自带的守护进程自动拉起，10 秒节流，不会疯狂重启。
更新了 App，或者把它挪了位置
打开 App 时会自动校正登录项，并把后台服务重启到新版本。

技术规格

版本2.5.3，2026 年 10 月 23 日发布
Mac 客户端macOS 13 Ventura 及以上；Apple 芯片与 Intel 芯片各有一个安装包，约 25 MB，不需要 Rosetta；也有两种芯片通用的版本，约 47 MB
Windows 客户端Windows 10 与 Windows 11，x64；按用户安装，不需要管理员权限；安装包约 23 MB
Linux 客户端x64 与 ARM64；.deb（Debian、Ubuntu 等）或 tar.gz（其他发行版），约 22 MB；需要 X11 桌面，或者带 XWayland 的 Wayland 桌面（GNOME、KDE 等默认都带）；GTK 3
服务器仅自建时需要部署；使用官方服务无需自备服务器。自建支持 Linux x86_64/ARM64、macOS 与 Windows 10/11 x64。
界面语言简体中文、繁體中文（台灣、香港）、English、日本語，默认跟随系统，可在设置里切换
同步的内容纯文本、带格式的文本、图片与截图、文件、文件夹，可以按类型关闭
传输WebRTC 数据通道，直连优先，打不通时经 TURN 中转；同一网络里经 mDNS 发现、UDP 8788 交换连接信息；多出口网络逐个探测每个出口；文件以 tar + zstd 流式打包
加密与身份DTLS 端到端加密；设备身份为 Ed25519 密钥；信令消息逐条签名
配对6 位配对码，5 分钟内有效，字符集去掉了 0/O、1/I 等易混字符；配对时人工核对安全指纹
自动同步上限默认 50 MB，可在 1 MB 到 1 GB 之间调整
隔空传送传给一台设备，不限大小，单个文件和整个文件夹都可以；局域网使用加密 TCP 快速通道（两端需 2.5.1），不可用时自动退回数据通道；外网与中转仍用 WebRTC；中断后续传，每个文件用 SHA-256 校验。Mac → Linux 虚拟机传 1 GB 实测 144.3 MB/s，之前为 18.7 MB/s；实际速度取决于网络与磁盘。
记录保留默认 3 天，可在 1 小时到 30 天之间调整，到期自动清理
实测速度局域网直连传输 20 MB 文件约 330 毫秒，校验和一致
技术栈后台服务与服务器用 Go（Windows 上纯 Go 调用 Win32，Linux 上纯 Go 走 X11 协议），界面用 Flutter（三个系统共用一套代码），消息定义用 Protocol Buffers
