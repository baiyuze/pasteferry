Everything you copied, on every computer

History keeps the last 3 days, ready to go back on the clipboard; click an image to preview it. Files under 50 MB have already arrived by the time you switch computers, and larger ones are a click away. To find something you copied earlier, search by its text or file name.

What happens when you copy

Text, images, files and whole folders all take the same path.

  1. Notice

    On Mac, the background service checks the clipboard's change count at short intervals; reading the count and types needs no permission and never shows a prompt. On Windows, the system tells it the moment you copy.

  2. Send

    Text travels inside the message. Images and files under 50 MB are streamed right away. Larger files are announced as a record and sent when you ask for them.

  3. Paste

    The other computer stores the content locally, then puts it on the clipboard. What you paste with ⌘V or Ctrl+V is a real local file.

Why not what's already there

Universal Clipboard needs the same Apple ID and both Macs close together. AirDrop asks you to accept every time. Messaging yourself means manual downloads and files left on someone else's server. With one Mac and one Windows PC, none of the built-in options work at all.

How it works

On the same network, devices find each other without a server. Across networks, official access or your own server exchanges connection information. Direct NAT traversal comes first; encrypted relay is used after direct failure. The diagram shows this general signaling and relay structure.

Direct on office networks too

Office networks with two ISPs, or carriers with a pool of NAT addresses, have several uplinks and pick one per destination. A single probe only reveals one of them, so connections end up on the relay. PasteFerry probes every uplink and tells the peer about all of them.

What it does

  • One shared port. All connections send and receive on one local UDP port, so the addresses learned from different servers line up.
  • Every uplink probed. Seven IP-diverse servers are queried from that port at once, yielding one address per uplink. Addresses poisoned by DNS are dropped first.
  • All of them sent to the peer. The peer tries each address; the one matching the real uplink gets through.
  • Uplinks remembered. If a round misses an uplink that keeps ports unchanged, its address is filled in as uplink IP plus local port.
  • A rule for who sends first. Some routers lock a port when the other side's packet arrives first. One side announces its addresses first; the other sends to them before announcing its own. Retries alternate the order.
  • Retry direct while idle.If direct traversal fails and relay is available, sync can use relay. When the connection is idle, the client can retry direct access and release the relay after success.

Your server can't see what you copy

  • No accounts, no stored content. A device's identity is an Ed25519 key, and its ID is derived from the public key, so the server verifies identity without a user table.
  • You compare fingerprints when pairing. Both screens show the same two lines: the fingerprint of each device's key. The server could swap keys in transit, but then the two screens would no longer match. That check is what stops a man in the middle.
  • Every message after that is signed, so the server can't impersonate your device. The direct channel's certificate is checked again after the handshake; a mismatch drops the connection.
  • The relay only forwards ciphertext. TURN carries encrypted packets, and relay credentials are issued per device and expire after 12 hours.
  • Same on the local network. What a device broadcasts on the LAN is an anonymous token that changes daily, not its name; the name is added only while Search nearby is open. Pairing still means comparing fingerprints, and every message is still signed.

When things go wrong

Every network is different. Each of these cases was considered, and each has a test.

Can't find the other computer on the network
Different subnets, guest networks and Wi‑Fi with client isolation block local discovery. Enter the address shown under the other computer's code when pairing; it's remembered afterwards, and if both computers change addresses you enter it once more in the device list.
The system blocks the local network
From macOS 15, the background service needs your permission to reach devices on the local network; Windows asks about the firewall on first run. If either isn't allowed, the app says so and links straight to the fix.
No direct path between the computers
Official access requests relay only after direct failure and within its current allowance. A custom server uses its own TURN relay instead. Content remains end-to-end encrypted in either case.
Public STUN servers unreachable
Public STUN is unreliable in some regions, including mainland China. Your server runs its own STUN, and clients prefer it.
Switching back to direct
If direct traversal fails and relay is available, sync can use relay. When the connection is idle, the client can retry direct access and release the relay after success.
The other computer sleeps, drops off or restarts
A connection that dies silently is noticed, closed and reconnected. Anything you copy meanwhile is kept and added to the other computer's history once it's back, without overwriting what's on its clipboard now.
Server connection drops
Reconnects automatically: the delay starts at 1 second and doubles up to 30, with jitter so devices don't all reconnect at once. Devices on the same network keep syncing.
File too large
Above the limit only a record is synced, pulled when you need it. If the source file is gone by then, you get a clear message instead of a vague failure.
Pasting into plain-text fields
Rich text copied from the web is written as both HTML and plain text, so no markup leaks into what you paste.
A file name Windows doesn't allow
Colons, question marks and a few other characters that are fine on a Mac arrive as the matching full-width characters, so the name still reads the same. Two names that differ only in case never overwrite each other.
Copying a password
On Windows, password managers mark what they copy as "don't record". PasteFerry skips it: not synced, not kept in the history.
Clipboard access not granted yet
Content isn't read, which would block on a prompt a background process can't show. The app asks you to grant access and links straight to the setting.
Background service crashes
launchd on Mac, and PasteFerry's own supervisor on Windows, restart it, throttled to once every 10 seconds.
App updated or moved
On launch the app re-points its login item and restarts the service on the new version.

Install

Install the app on each computer. On the same network you can pair right away; across networks, pick a way for them to find each other. First time? Follow the quick start.

Mac

  1. Download the DMG, open it and drag PasteFerry into Applications.There's one for Apple silicon and one for Intel; the download page shows how to tell which your Mac has.
  2. Open it from Applications.The first time, macOS says it can't verify the developer: PasteFerry isn't notarized by Apple yet. Go to System Settings → Privacy & Security and click Open Anyway near the bottom. You only do this once.
  3. Click Turn on background sync. When macOS asks whether PasteFerry may read the clipboard or find devices on your local network, allow both.
  4. For different networks, enable Settings → Use official service on each computer. No server address is needed. Custom hosting remains optional.
Download for Mac

Windows

  1. Run PasteFerry-Setup.exe. It installs for the current user, no administrator rights needed.PasteFerry isn't code-signed yet, so Windows says "Windows protected your PC": click More info, then Run anyway. To skip the installer, get the portable zip.
  2. Open PasteFerry and click Turn on background sync. Allow it if Windows Firewall asks. After you close the window it keeps running in the notification area.
  3. For different networks, enable Settings → Use official service on each computer. No server address is needed. Custom hosting remains optional.
Download for Windows

Linux

  1. On Ubuntu, Debian and similar, download the .deb and run sudo apt install ./PasteFerry-linux-amd64.deb; on other distributions, download the tar.gz, extract it and run ./PasteFerry/install.sh.
  2. Open PasteFerry from the app menu and click Turn on background sync. From then on it starts when you log in.
  3. For different networks, enable Settings → Use official service on each computer. No server address is needed. Custom hosting remains optional.

Questions

Why do .uuremote_ files keep appearing while UU Remote is running?

UU Remote writes temporary placeholder files to the system clipboard. Older PasteFerry clients recorded and forwarded them as ordinary files. Version 1.3.2 filters the confirmed placeholder naming pattern on send and receive, and removes placeholder-only history on startup. Ordinary empty, hidden and large files are unaffected. The 50 MB threshold only controls automatic transfer; UU’s UDP P2P setting is unrelated. Upgrade both clients. Other clipboard sync tools may still duplicate ordinary content.

How is this different from Universal Clipboard?

Mac, Windows and Linux. Text, images, files, whole folders. No shared account required. Now connect across networks by enabling official access, with no server to host. Direct connections first, end-to-end encryption throughout.

If your Macs share an Apple ID, sit side by side, and you mostly copy text, the built-in feature is already enough.

Can the server see what I copy?

It cannot decrypt copied content: direct traffic stays between your devices, and relay forwards end-to-end encrypted packets. Official access retains essential device and quota statistics, described in the privacy notice. The public client and server source does not by itself prove how private production storage is operated.

Does it connect directly on office networks with several uplinks?

Yes. These networks pick an uplink per destination. PasteFerry probes several servers from one port to learn its address on every uplink and sends them all to the peer, which tries each one. A Mac behind a 4-uplink office network connects directly to a home connection in our tests. Peers behind NATs that randomize ports still fall back to the relay.

Do I need my own server?

No. For different networks, enable official access on both computers. No cloud VM or address to configure. It is off by default and currently includes 100 MB/day of relay traffic; direct connections do not use that allowance. LAN, self-hosting and Tailscale remain available.

No public IP at home. Can I sync between home and the office?

No. For different networks, enable official access on both computers. No cloud VM or address to configure. It is off by default and currently includes 100 MB/day of relay traffic; direct connections do not use that allowance. LAN, self-hosting and Tailscale remain available.

Both computers are on the same network. Why can't they find each other?

Check that they're really on the same subnet: wired and Wi‑Fi in many offices, guest networks, and Wi‑Fi with client isolation don't let devices see each other. In that case, on the computer entering the code, click On a different subnet? and enter the address shown under the other computer's code.

On Windows, allow PasteFerry when the firewall asks on first run; if you clicked Cancel, click Allow under Settings → Local network. On a Mac, turn on PasteFerry Daemon in System Settings → Privacy & Security → Local Network. More in the same network guide.

Windows? Linux? iPhone?

Windows 10 and 11 (x64) are supported and work together with Macs. Files you paste on Windows are real files you can drop into Explorer or Office.

Linux desktops on x64 and ARM64 are supported too: X11, or Wayland with XWayland (GNOME, KDE and others include it by default). Files you copy paste straight into the file manager.

iPhone and iPad aren't supported: iOS doesn't let apps watch the clipboard in the background, so copy-and-it's-there can't work.

Why does the system warn me the first time?

PasteFerry isn't notarized by Apple yet, and the Windows build isn't code-signed yet; both require paid certificates.

On Mac, open System Settings → Privacy & Security and click Open Anyway near the bottom. On Windows, click More info and then Run anyway in the "Windows protected your PC" prompt. You only do this once.

What about large files?

By default, anything under 50 MB is pushed to the other computer as you copy it, so you can paste right away. Larger files sync as a record; pull them from the history when you need them. The limit is adjustable in Settings.

Is it free? Can my company use it?

Yes. PasteFerry is open source under the GNU AGPL-3.0, so individuals and companies can use and modify it for free. If you distribute it, or offer a modified version over a network, you publish your source under the same license.

Is official relay unlimited?

The current default is 100 MB per machine quota group per day, upload plus download, resetting at midnight Beijing time. Reinstalling does not guarantee a fresh allowance. The usage page shows the actual limit, remaining amount and update time. Direct connections still work when relay allowance runs out. Allowances and availability may change; check the app.
