隔空貼

運作原理

按下複製之後發生了什麼，兩台電腦怎樣找到彼此、怎樣直連，打不通時怎麼辦。

按下複製之後

文字、圖片、檔案、整個資料夾，都走同一條路。

  1. 偵測

    在 Mac 上，背景服務每隔一小段時間查看一次剪貼簿的變更計數，只看計數和類型，不需要授權，也不會跳出系統提示；在 Windows 上，複製的那一刻系統就會通知它。

  2. 傳輸

    文字隨訊息一起送出；50 MB 以內的圖片和檔案打包成串流立即推送；更大的檔案只送出一筆記錄，等你需要時再傳。

  3. 貼上

    另一台電腦先把內容存到本機，再寫入剪貼簿。按下 ⌘V 或 Ctrl+V 貼上的，就是本機上真正的檔案。

隔空貼的連線方式

同一網路裡，裝置不需伺服器就能找到彼此；跨網路時，「服務」或自建伺服器協助交換連線資訊。優先打洞直連，失敗後才使用加密中繼。下圖展示通用的信令與中繼結構。

公司網路也能直連

公司雙線路、電信業者位址池這類網路有多個出口，會依目的位址決定走哪一個。只偵測一次，只會知道其中一個出口，結果只能經伺服器中繼。隔空貼會偵測每個出口，把位址全部告訴對方。

做了什麼

  • 共用一個連接埠。所有連線都從同一個本機 UDP 連接埠收發，向不同伺服器查到的位址才對得上。
  • 偵測每個出口。在這個連接埠上同時詢問 7 台 IP 分散的伺服器，網路有幾個出口就拿到幾個位址；遭 DNS 汙染的位址會先過濾掉。
  • 全部告訴對方。對方逐一嘗試，與實際出口相符的那一個就能打通。
  • 記住見過的出口。某次漏掉的出口，如果它不會改變連接埠，就用「出口 IP + 本機連接埠」推算補上。
  • 講好誰先送封包。有些路由器收到對方先到的封包，會把連接埠佔住。一方先公布出口位址，另一方先往那邊送封包，再公布自己的；重試時兩種順序輪流使用。
  • 閒置時重試直連。直連失敗且中繼可用時，先透過中繼保持同步。連線閒置時可重試打洞，成功後切回直連並釋放中繼。

用真實的網路拓撲驗證

NAT 打洞實驗室用 Linux 網路命名空間與 iptables 搭出這些拓撲，用隔空貼真正的連線程式碼各跑一遍，每次提交程式碼都會自動執行。

實測：一台在 4 個出口的公司網路裡的 Mac 與家裡的 Mac，改良前只能中繼，速度被伺服器頻寬限制在 0.6 MB/s；改良後可以直連，連上伺服器後約 3 秒就建立連線。

量測過程、設計取捨與踩過的坑，請見技術說明。

出問題的時候會怎樣

每個人的網路環境都不一樣。下面這些情況都考慮過，也都有對應的測試。

在同一個網路裡找不到對方
不同網段、訪客網路、開了 AP 隔離的 Wi‑Fi，都會擋住區域網路探索。配對時輸入對方配對碼下方顯示的位址就行；之後位址會被記住，兩邊都換了位址時，在裝置清單裡幫它重新輸入一次。
系統擋住區域網路連線
從 macOS 15 起，背景服務要連線區域網路裡的裝置，需要你允許；Windows 第一次執行時，防火牆會跳出詢問。沒有允許時，App 會提示，並提供直達設定的按鈕。
兩台電腦打不通直連
服务模式在直連失敗後，依目前額度申請中繼；自建模式使用自己的 TURN 中繼。兩種方式的內容均保持端到端加密。
連不上公共 STUN 伺服器
在中國大陸連公共 STUN 時通時斷。伺服器內建 STUN，用戶端會優先使用它。
從中繼切回直連
直連失敗且中繼可用時，先透過中繼保持同步。連線閒置時可重試打洞，成功後切回直連並釋放中繼。
對方睡眠、斷線或重新開機
連線悄悄斷了也能察覺，會立即關閉並重新連線。這段期間複製的內容會先記下來，連上後補送到對方的複製記錄裡，但不會覆蓋對方當下剪貼簿裡的內容。
伺服器斷線
自動重新連線，間隔從 1 秒開始加倍、最長 30 秒，並加上隨機抖動，避免一大群裝置同時重連。同一個網路裡的裝置不受影響，照常同步。
檔案太大
超過上限的只同步一筆記錄，需要時再拉取。拉取時如果原始檔案已經被刪除，會明確告訴你，而不是莫名其妙地失敗。
傳檔案時中斷
隔空傳送傳到一半斷網、睡眠或程式結束，30 分鐘內連上會從中斷處自動接著傳；更晚的話點「繼續」，同樣從中斷處開始。每個檔案都會校驗，不完整的不會出現在儲存位置。
貼到只接受純文字的地方
從網頁複製的帶格式文字，會同時寫入 HTML 和純文字兩份，貼到哪裡都不會冒出標籤。
檔名在 Windows 上不合法
Mac 上可以用的冒號、問號等字元，收到時會換成對應的全形字元，檔名照樣看得懂；只差在大小寫的兩個檔案也不會互相覆蓋。
複製的是密碼
在 Windows 上，密碼管理工具複製的內容會帶一個「不要記錄」的標記，隔空貼看到就跳過：不同步，也不會進入複製記錄。
還沒授權讀取剪貼簿
不去讀取內容，否則背景程序會卡在一個看不見的系統對話框上。App 裡會提示你去授權，並提供直達設定的按鈕。
背景服務當掉
Mac 上由系統的 launchd、Windows 上由隔空貼內建的守護程式自動重新啟動，每次至少間隔 10 秒，不會無限重啟。
更新了 App，或把它搬到別的位置
打開 App 時會自動修正登入項目，並把背景服務重新啟動到新版本。

技術規格

版本2.5.4，2026 年 10 月 26 日發布
Mac 用戶端macOS 13 Ventura 以上；Apple 晶片與 Intel 晶片各有一個安裝檔，約 25 MB，不需要 Rosetta；也有兩種晶片通用的版本，約 47 MB
Windows 用戶端Windows 10 與 Windows 11，x64；只為目前使用者安裝，不需要系統管理員權限；安裝檔約 23 MB
Linux 用戶端x64 與 ARM64；.deb（Debian、Ubuntu 等）或 tar.gz（其他發行版），約 22 MB；需要 X11 桌面，或附有 XWayland 的 Wayland 桌面（GNOME、KDE 等預設都有）；GTK 3
伺服器僅自建時需要部署；使用服務不需自備伺服器。自建支援 Linux x86_64/ARM64、macOS 與 Windows 10/11 x64。
介面語言簡體中文、繁體中文（台灣、香港）、English、日本語，預設跟隨系統，可在設定裡切換
同步的內容純文字、帶格式的文字、圖片與螢幕截圖、檔案、資料夾，可依類型個別關閉
傳輸WebRTC 資料通道，優先直連，打不通時經 TURN 中繼；同一個網路裡透過 mDNS 探索、UDP 8788 交換連線資訊；多出口網路逐一偵測每個出口；檔案以 tar + zstd 串流打包
加密與身分DTLS 端對端加密；裝置身分為 Ed25519 金鑰；信令訊息逐則簽章
配對6 碼配對碼，5 分鐘內有效，字元集去掉了 0/O、1/I 等容易混淆的字元；配對時人工核對安全指紋
自動同步上限預設 50 MB，可在 1 MB 到 1 GB 之間調整
隔空傳送傳給一台裝置，不限大小，單一檔案和整個資料夾都可以；區域網路使用加密 TCP 快速通道（兩端需 2.5.1），無法使用時自動退回資料通道；外網與中繼仍用 WebRTC；中斷後續傳，每個檔案用 SHA-256 校驗。Mac → Linux 虛擬機傳 1 GB 實測 144.3 MB/s，之前為 18.7 MB/s；實際速度取決於網路與磁碟。
好友加好友用 F 開頭的 7 位好友碼，經區域網路或服務交換，可核對安全碼；好友之間只能互傳檔案和圖片，可附 200 字以內的備註，每批都要對方接受；剪貼簿、複製記錄、裝置列表不給好友；收到的檔案去掉可執行權限，Mac 上加上隔離標記；兩端需 2.6
記錄保留預設 3 天，可在 1 小時到 30 天之間調整，到期自動清除
實測速度區域網路直連傳輸 20 MB 檔案約 330 毫秒，檢查碼一致
技術堆疊背景服務與伺服器用 Go（Windows 上以純 Go 呼叫 Win32，Linux 上以純 Go 走 X11 協定），介面用 Flutter（三個系統共用一套程式碼），訊息定義用 Protocol Buffers
